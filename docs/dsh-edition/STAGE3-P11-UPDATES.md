# Шаг 9: обновления больше не могут подменить форк оригиналом

**Дата:** 2026-11-13  
**Точка отката:** `7520396ad7d6b010365839d1547a1c74b2097324`

## В чём была опасность

`update.rs` спрашивал релизы у **`Louis-CFM/coucou`** — то есть у оригинала.
Обновление заменяет установленное приложение, поэтому однажды предложенный
апстрим-релиз quietly вернул бы на место оригинальный Coucou: без моста DSH и без
всего, что на нём построено.

Раньше это прикрывалось только тем, что в изолированной тестовой сборке
обновления отключены (`build_mode::is_test()`). В постоянной сборке форка защиты
не было.

## Что сделано

| Было | Стало |
|---|---|
| `RELEASES_URL` → `Louis-CFM/coucou` | `releases_url()` → `FORK_REPO` = `Good-Eli/coucou-dsh-edition` |
| `RELEASES_PAGE` → страница оригинала | `releases_page()` → страница форка |
| ссылка «All changes» вела на релизы оригинала | ведёт на релизы форка |

Источник сделан функцией, а не константой: его можно проверить тестом и
переопределить переменной `COUCOU_UPDATE_REPO`, не трогая исходник.

`UPSTREAM_REPO` оставлен в коде **только** как имя, с которым сравнивает тест.

## Тесты-стражи

- `this_build_never_asks_upstream_for_an_update` — адрес релизов не содержит
  апстрим;
- `the_default_source_is_the_forks_own_repository` — по умолчанию форк, и форк
  не равен оригиналу;
- `the_release_urls_keep_the_shape_github_answers` — форма адресов не изменилась.

## Проверка собранного бинарника

Строковый поиск по `coucou.exe`:

```
fork repo present:    True      (Good-Eli/coucou-dsh-edition)
upstream API url:     False     (api.github.com/repos/Louis-CFM/coucou/releases)
upstream repo string: False     (Louis-CFM/coucou — нигде)
```

То есть в релизной сборке ссылок на оригинал нет вообще: константа `UPSTREAM_REPO`
существует только в тестовой конфигурации и в бинарник не попадает.

## Что осталось: шаги 10–11

- прогон приёмки на установленной копии;
- `whats-new.json` и запись в CHANGELOG — по правилам репозитория для релиза.
