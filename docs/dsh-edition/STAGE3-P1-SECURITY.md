## 2. Что было не так с каналом

Node не умеет задавать DACL именованного канала:

- `uv_pipe_bind` вызывает `CreateNamedPipeW` с `NULL` в `SECURITY_ATTRIBUTES`;
- `server._handle.fd` равен `-1`, поэтому ни прочитать, ни изменить DACL нельзя;
- у принятого соединения handle тоже `-1` — проверить SID клиента невозможно.

Замер фактического DACL канала, созданного Node:

```
D:(A;;FA;;;SY)(A;;FA;;;BA)(A;;FA;;;<SID>)(A;;FR;;;WD)(A;;FR;;;AN)
```

`WD` — Everyone, `AN` — Anonymous, обоим доступно чтение. Это и был реальный дефект.

Канал, созданный с нашим дескриптором (проверено отдельным процессом):

```
O:<SID>D:P(A;;FA;;;SY)(A;;FA;;;BA)(A;;FA;;;<SID>)
```

## 3. Архитектура канала

```
DSH host (Electron)
  └─ плагин bridge.mjs        — только текст, никакого koffi
       └─ pipe-host.mjs       — отдельный процесс, koffi, CreateNamedPipeW
            └─ worker         — ConnectNamedPipe + PeekNamedPipe/ReadFile
Coucou → \\.\pipe\coucou-dsh-<SID>
```

Плагин общается с хостом канала по stdin/stdout и IPC. Причина разделения — §5.

## 5. Инцидент: два падения DSH

**Симптом.** Хост завершился с кодом `3221226356` (`0xC0000374`,
`STATUS_HEAP_CORRUPTION`), логи:
`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-2026-11-11T21-36-{23,59}Z-host.log`.

**Причина.** Первая версия создавала канал через `koffi` **внутри процесса DSH**.
Нативный вызов повредил кучу хоста. Это моя ошибка, не DSH.

**Второй дефект, найденный при переносе.** В отдельном процессе чтение через
блокирующий `ReadFile` вешало `WriteFile` из другого потока на том же handle —
запись в канал не доходила. Исправлено: чтение опрашивает `PeekNamedPipe`.

**Что сделано, чтобы не повторилось.**
1. Нативный код вынесен из процесса DSH в отдельный процесс.
2. `pipe-host.mjs` не может уронить DSH: при его падении плагин видит смерть канала
   и перестаёт перехватывать разрешения — DSH показывает свои диалоги.
3. Падение хоста больше не считается нормой: `onFatal` логируется как ошибка
   (плановый останов отличается флагом `#stopping`).

**Профиль DSH был повреждён.** Прерванная запись обрезала
`cordis.patch.yml` до 1588 байт и потеряла запись `ui-conversation`.
Профиль восстановлен из бэкапа побайтно (SHA-256 совпал с исходным
`5D1697C4…0EE10F`). Теперь профиль пишется атомарно: временный файл → проверка
числа записей → `Move-Item`.

## 7. Известные ограничения

1. **Один клиент.** Второе подключение отбивается; окно между отключением и
   повторным `ConnectNamedPipe` закрыто самим протоколом (без токена ничего не уходит).
2. **koffi зависит от раскладки DSH.** Путь ищется в `resources/app.asar/dsh/node_modules`.
   Если не найден, канал не поднимается и разрешения не перехватываются — это
   осознанный fail-closed, а не деградация до незащищённого канала.
   Аварийный режим `allowUnhardenedPipe` существует, но по умолчанию выключен.
3. **Проверка SID клиента не делается.** Node не отдаёт handle, поэтому
   аутентификация — это токен из файла с приватным ACL. Это и есть граница доверия:
   кто прочитал файл, тот и есть пользователь.
4. **`skipVersionCheck`** позволяет работать с непроверенной версией DSH. По умолчанию выключен.
