# Приоритет 2 — изолированная тестовая сборка Coucou

**Дата:** 2026-11-12  
**Статус:** в работе. Ниже — инвентаризация общих ресурсов (§2 задания) и решения по каждому.

## 1. Как включается изоляция

```powershell
$env:COUCOU_DATA_SUFFIX = '-dsh-test'   # обязателен для тестовой сборки
```

Переменная действует **только** в бинарнике, собранном с `COUCOU_TEST_BUILD=1`.
Обычная сборка её игнорирует — случайная переменная в окружении не может
увести данные рабочего Coucou в другое место.

Тестовая сборка **отказывается запускаться без суффикса**: без него она
использовала бы каталоги, канал и ключи установленной копии, а этого нельзя
допустить. Вместо тихого выхода показывается окно с объяснением.

Суффикс проверяется: начинается с `-`, 2–32 символа, только `A-Za-z0-9._-`,
без `..`, пробелов и разделителей пути. Всё остальное отвергается.

## 2. Инвентаризация общих ресурсов

### 2.1. Файловые каталоги

| Ресурс | Оригинал | Тестовая сборка | Как изолируется |
|---|---|---|---|
| Настройки | `%APPDATA%\Coucou\settings.json` | `%APPDATA%\Coucou-dsh-test\settings.json` | `platform::config_dir()` |
| Почта | `%APPDATA%\Coucou\mail\` | `%APPDATA%\Coucou-dsh-test\mail\` | через `config_dir()` |
| WhatsApp | `%APPDATA%\Coucou\whatsapp.json` | `%APPDATA%\Coucou-dsh-test\whatsapp.json` | через `config_dir()` |
| Звуки | `%APPDATA%\Coucou\sounds\` | `%APPDATA%\Coucou-dsh-test\sounds\` | через `config_dir()` |
| Состояние обновления | `%APPDATA%\Coucou\update.json` | не используется (обновления выключены) | через `config_dir()` + гейт |
| Журнал | `%LOCALAPPDATA%\Coucou\coucou.log` | `%LOCALAPPDATA%\Coucou-dsh-test\coucou.log` | `platform::local_dir()` |
| Хук-релей | `%LOCALAPPDATA%\Coucou\bin\coucou-hook.exe` | `%LOCALAPPDATA%\Coucou-dsh-test\bin\` | через `local_dir()` |
| Входящие файлы | `%LOCALAPPDATA%\Coucou\inbox\` | `%LOCALAPPDATA%\Coucou-dsh-test\inbox\` | через `local_dir()` |
| Рекап | `%LOCALAPPDATA%\Coucou\recap.json` | `%LOCALAPPDATA%\Coucou-dsh-test\recap.json` | через `local_dir()` |
| Заметки | `%LOCALAPPDATA%\Coucou\Notes\` | `…\Coucou-dsh-test\Notes\` | через `local_dir()` |
| Flow | `%LOCALAPPDATA%\Coucou\Flow\` | `…\Coucou-dsh-test\Flow\` | через `local_dir()` |
| Модели речи | `%LOCALAPPDATA%\Coucou\Models\` | `…\Coucou-dsh-test\Models\` | через `local_dir()` |
| Релей CLI | `%LOCALAPPDATA%\Coucou\relay\` | `…\Coucou-dsh-test\relay\` | через `local_dir()` |
| Статус-лайн | `%LOCALAPPDATA%\Coucou\statusline-previous.json` | `…\Coucou-dsh-test\` | через `local_dir()` |
| Профиль WebView2 | `%LOCALAPPDATA%\<identifier>\EBWebView` | `%LOCALAPPDATA%\Coucou-dsh-test\WebView2` | `WEBVIEW2_USER_DATA_FOLDER` до старта webview |

Все пути в коде идут через две функции (`config_dir`, `local_dir`), поэтому одной
правки достаточно для всего списка. Отдельно пришлось занять профиль WebView2:
Tauri по умолчанию кладёт его в каталог по идентификатору приложения, общий для
двух сборок.

### 2.2. Named Pipes — два независимых канала

| Канал | Оригинал | Тестовая сборка | Правило |
|---|---|---|---|
| **А. Релей хуков** (Coucou — сервер) | `\\.\pipe\coucou-<SID>` | `\\.\pipe\coucou-dsh-test-<SID>` | имя зависит от суффикса |
| **Б. DSH Host Bridge** (DSH — сервер, Coucou — клиент) | `\\.\pipe\coucou-dsh-<SID>` | **то же самое имя, без изменений** | суффикс не применяется |

Канал Б не переименовывается намеренно: сервер создаёт DSH, а не Coucou, и
переименование сломало бы подключение. Тестовая сборка подключается к уже
существующему каналу. Защита от конфликта: сервер DSH принимает **одного**
клиента за раз, второй отбивается; тестовая сборка не создаёт второй сервер.

Хук `coucou-hook.exe` получает имя канала из своего окружения
(`COUCOU_DATA_SUFFIX`), потому что его запускает агент, а не Coucou. Без
переменной хук идёт на оригинальный канал — то есть тестовая сборка никогда не
перехватывает трафик установленной копии.

### 2.3. Единственный экземпляр (mutex)

| Что | Оригинал | Тестовая сборка |
|---|---|---|
| Mutex одиночного запуска | `<identifier>-sim` (плагин Tauri) | `coucou-dsh-test-single-instance` (свой) |

Плагин `tauri-plugin-single-instance` версии 2.5.0 на Windows берёт идентификатор
приложения из конфигурации и игнорирует настраиваемый `dbus_id`. С общим
идентификатором тестовая сборка передала бы аргументы установленной копии и
завершилась. Поэтому в тестовом режиме плагин не подключается вообще, а одиночный
запуск обеспечивает собственный mutex с суффиксом.

### 2.4. Credential Manager

| Что | Оригинал | Тестовая сборка |
|---|---|---|
| Служба | `fr.louisraille.coucou` | `fr.louisraille.coucou-dsh-test` |

Критично: без этого тестовая сборка читала бы и **перезаписывала** настоящие
API-ключи пользователя. Суффикс применяется к имени службы, поэтому наборы
секретов полностью независимы.

### 2.5. Автозапуск

| Что | Оригинал | Тестовая сборка |
|---|---|---|
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Coucou` | есть | **не создаётся и не меняется** |
| `HKCU\…\Run\CoucouDshBridge` | есть (старый мост) | **не трогается** |

В тестовом режиме плагин автозапуска вообще не загружается, а сохранение
настроек не вызывает менеджер автозапуска. Тестовая сборка не устанавливает себя
в систему и не регистрирует обработчиков протоколов.

### 2.6. Обновления

| Что | Оригинал | Тестовая сборка |
|---|---|---|
| Проверка релизов | раз в 6 часов с api.github.com | **выключено** |
| Установка | скачивает MSI/NSIS и запускает | **выключено** |

Иначе тестовая сборка предложила бы поставить поверх себя официальный релиз.

### 2.7. Прочие общие ресурсы

| Ресурс | Решение |
|---|---|
| Конфигурации агентов (`.claude/settings.json` и др.) | тестовая сборка **отказывается** писать: `hooks::write`, `status_line_write`, `agents::apply` возвращают ошибку |
| mDNS-объявление телефона | `_coucou._tcp` → `_coucou-dsh-test._tcp` (телефон не найдёт тестовую сборку) |
| Глобальные горячие клавиши | общие с ОС; вторая регистрация может не удаться — известное ограничение |
| Значок в трее | два значка при двух запущенных копиях — известное ограничение |
| Временные файлы | уже содержат PID, конфликтов нет |
| Идентификатор приложения (bundle identifier) | не меняется; расхождение закрыто mutex-ом, профилем WebView2 и каталогами |
## 3. Результаты проверки

Живой прогон: обе сборки запущены одновременно.

| № | Проверка | Результат |
|---|---|---|
| 1 | Оригинал использует прежние каталоги | `%APPDATA%\Coucou\settings.json` — SHA-256 и mtime не изменились; в `%LOCALAPPDATA%\Coucou` те же 22 файла |
| 2 | Тестовая сборка создаёт только свои каталоги | создан `%LOCALAPPDATA%\Coucou-dsh-test` с `bin\coucou-hook.exe`, `WebView2\EBWebView`, `coucou.log` |
| 3 | Настройки независимы | оба процесса читают из своих путей (`config_dir()`); файл `settings.json` тестовой сборки появится при первом сохранении настроек — ручная проверка ниже |
| 4 | Внутренние Named Pipes различаются | `\\.\pipe\coucou-<SID>` и `\\.\pipe\coucou-dsh-test-<SID>` существовали одновременно |
| 5 | Тестовый Coucou подключается к правильному DSH Bridge | имя DSH-канала не изменилось; клиентская часть — Приоритет 3, поэтому подключение ещё не реализовано |
| 6 | Конфликт единственного клиента | второй сервер на канале DSH не создаётся: канал принадлежит DSH, плагин принимает одного клиента (проверено в Приоритете 1) |
| 7 | DSH получает состояние сессий | проверено в Приоритете 1; изоляция это не меняет |
| 8 | Старый мост и автозапуск целы | `HKCU\…\Run\Coucou` и `HKCU\…\Run\CoucouDshBridge` без изменений; 4 файла моста на месте |
| 9 | Запуск/остановка тестовой сборки не меняют оригинал | хэш `settings.json` одинаков до и после; после остановки исчез только суффиксный канал |

Дополнительно: тестовая сборка **без** `COUCOU_DATA_SUFFIX` не запускается — показывает
окно с объяснением, каталоги не создаёт, журнал оригинала не трогает.

## 5. Запуск тестовой сборки

```powershell
cd C:\LocalAI\coucou\work\coucou-dsh\windows\scripts
.\dsh-test-build.ps1      # собрать (один раз или после правок)
.\dsh-test-run.ps1        # запустить
.\dsh-test-run.ps1 -ShowPaths   # показать пути и имена каналов
.\dsh-test-run.ps1 -Stop        # остановить только тестовую сборку
```

Скрипт запуска останавливает только процессы, чей путь — тестовая сборка. Установленный
Coucou и старый мост он не трогает.

## 6. Полное удаление тестовых данных

```powershell
.\dsh-test-run.ps1 -Stop
Remove-Item -Recurse -Force "$env:APPDATA\Coucou-dsh-test"
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Coucou-dsh-test"
Remove-Item -Recurse -Force "C:\LocalAI\build\coucou-dsh"
# Секреты тестовой сборки (если что-то сохранялось):
cmdkey /list | Select-String "fr.louisraille.coucou-dsh-test"
```

Ключи Credential Manager с суффиксом удаляются по одному через `cmdkey /delete:<target>`;
записи оригинальной службы `fr.louisraille.coucou` при этом не затрагиваются.

## 7. Восстановление

Ничего в оригинале не менялось, поэтому восстановление не требуется. Если тестовая
сборка когда-либо оставит следы:

1. `.\dsh-test-run.ps1 -Stop`.
2. Удалить каталоги из §6.
3. При необходимости вернуть профиль DSH из бэкапа — это касается только Приоритета 1.

## 8. Известные ограничения

1. **Горячие клавиши.** Тестовая сборка не может зарегистрировать те же
   `Ctrl+Alt+…`, что и запущенный оригинал: в журнале `HotKey already registered`.
   Это ожидаемо и не мешает остальному.
2. **Значок в трее.** При двух запущенных копиях видно два значка.
3. **Диктовка Flow** ставит глобальный перехват клавиатуры; пользоваться ею
   одновременно в двух копиях не следует.
4. **Настройки тестовой сборки.** Файл `%APPDATA%\Coucou-dsh-test\settings.json`
   появляется при первом изменении настроек в интерфейсе. До этого сборка работает
   на значениях по умолчанию — это и есть доказательство, что она не читает
   настройки оригинала.
5. **Сборка.** Прямая сборка в каталоге репозитория иногда падает с `LNK1104`
   (та же ошибка, что в базовой сборке). Скрипт `dsh-test-build.ps1` собирает в
   ASCII-зеркале `C:\LocalAI\build\coucou-dsh`, где сборка проходит стабильно.

## 9. Инцидент: каталог рабочего пространства переименован

Во время работы каталог `C:\LocalAI\сoucou` (кириллическая «с») стал
`C:\LocalAI\coucou` (латинская «c»). Кто именно переименовал — не установлено;
данные, git-история и все изменения сохранились, ничего не потеряно. Проверено:
имя состоит из кодов `U+0063 U+006F U+0075 U+0063 U+006F U+0075`, старый путь
больше не существует, репозиторий и файлы на месте.

Побочный эффект: путь стал ASCII, что снимает часть проблем MSVC с не-ASCII
путями. Скрипты и документация обновлены под новый путь.
